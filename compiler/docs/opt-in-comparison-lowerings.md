# Opt-in comparison lowerings: unsigned `i32` fusion and branchless booleans (fork plan §3.4, §3.2)

Status: implemented on `fuse-branch-conditions` (`9e613f66`), 2026-10-18. The upstream side
(§3.4 "discuss with maintainers first") has not happened; the draft for that discussion is in
[upstream-pr/OPEN_PRS.md](upstream-pr/OPEN_PRS.md).

## Unsigned `i32` compare fusion (§3.4)

**Why.** After the original fusion and its extensions, unsigned `i32` comparisons with a
variable operand or a constant that is not a power-of-two bound are the largest group still
lowered to a helper call plus a test of its 0/1 result: in the static census
(`data/compiler-census/`) `Shaded.i32_{lt,gt,le,ge}_u` has 4,003 call sites in QuickJS
(Javy provider), 2,481 in .NET and 1,078 in Go.

**Constraint.** The JVM has no unsigned `int` compare. `Integer.compareUnsigned` and the
`MIN_VALUE` bias both produce the pattern C2 on Java 11 to 17 can miscompile (JDK-8376400); that
is why `I32_GE_U`/`I32_LT_U` go through `MemCopyWorkaround` and why the fusion PR leaves them
unfused (see `BranchCondition.ofComparison`).

**Emission.** `Integer.compareUnsigned(a, b)` followed by `if<cond>` on its sign
(`BranchCondition.I32_{LT,GT,LE,GE}_U`, prefix `ICMP_UNSIGNED`), exactly like the existing
unsigned `i64` fusion through `Long.compareUnsigned`. The plan's alternative for constant
operands, biasing the constant at compile time (`C ^ MIN_VALUE`) and the variable with
`ixor`, is not smaller: `ldc MIN_VALUE; ixor; ldc C'; if_icmp<cond>` is 8 to 9 bytes against
6 for `invokestatic; if<cond>`. On Java 21, `Integer.compareUnsigned` is a C2 intrinsic
(`PrintInlining` reports `(intrinsic)`, see [inlining-at-8000-bytes.md](inlining-at-8000-bytes.md)).

**Who may turn it on.**

| entry point | default | why |
| --- | --- | --- |
| `Compiler.Builder.withUnsignedCompareFusion` | off | the generated classes may run anywhere |
| `MachineFactoryCompiler` (and `MachineFactory`) | on exactly when `MemCopyWorkaround` is off: Java 18+ and `-Dendive.memCopyWorkaround` not `true`; `-Dendive.compiler.unsignedCompareFusion` overrides | the code runs in the JVM that compiles it |
| build-time compiler `Config`, Maven plugin `unsignedCompareFusion`, CLI `--unsigned-compare-fusion` | off | output runs on unknown JVMs; documented with the Java 18 requirement |

`MachineFactoryCompiler`'s cache key now includes the options, since they change the bytecode.

## Branchless booleans (§3.2)

**Why.** Comparisons whose result is stored or used arithmetically still call their helper; Go
keeps 953 `I64_EQZ` calls after fusion.

**Emission** (`CompilerOpCode.BRANCHLESS_BOOL`, after fusion, only for results not consumed by
a branch):

| op | sequence | bytes (call: 3) |
| --- | --- | ---: |
| `i32.ne` / `i32.eq` | `ixor`, then nez / eqz | 7 / 9 |
| `i32` nez (internal) / `i32.eqz` | `dup; ineg; ior; bipush 31; iushr` / + `iconst_1; ixor` | 6 / 8 |
| `i64.ne` / `i64.eq` | `lxor`, then nez / eqz | 8 / 10 |
| `i64.eqz` | `dup2; lneg; lor; bipush 63; lushr; l2i; iconst_1; ixor` | 9 |

`(x | -x)` has its sign bit set exactly when `x != 0` (`MIN_VALUE` included: `-MIN_VALUE` is
`MIN_VALUE`).

**Default: off.** Every site grows by 3 to 7 bytes; on the corpus that is +0.07 % (code.wasm)
to +0.42 % (Go) of `func_*` bytecode. The large-method benchmark favours it, but the split
workloads show no gain and slightly slower compilation
([large-method-benchmark.md](large-method-benchmark.md)), so it stays opt-in
(`-Dendive.compiler.branchlessBooleans=true` or `withBranchlessBooleans(true)`).

## Tests

`CompilerOptionsTest` runs every condition fixture (`branch_conditions`, `branch_conditions_const`,
`bool_values`, `narrowing`, `ref_conditions`, `ref_eq`) compiled under all four option
combinations against the interpreter, with traps compared, and checks structurally that unsigned
comparisons fuse only when enabled and that value-context comparisons become `BRANCHLESS_BOOL`.
`bool_values.wat` is generated by `data/compiler-census/fixtures/gen_bool_values_wat.py`.
Because `MachineFactoryCompiler` enables unsigned fusion on Java 21, the 34,121 spec tests of
`compiler-tests` and the `machine-tests` now run with it.
